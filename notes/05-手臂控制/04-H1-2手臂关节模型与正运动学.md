## 1. 为什么抓取任务需要 URDF

SDK 电机编号解决的是“向哪个电机槽位读取或写入数据”；URDF 描述的是：

- 关节连接了哪些父、子连杆。
- 关节在父连杆中的安装位置与姿态。
- 关节绕哪根轴旋转。
- 模型记录的关节角度、力矩和速度上限。
- 连杆的视觉、碰撞和惯性属性。

正运动学和逆运动学都需要使用这些几何关系。

## 3. 一个旋转关节的 URDF 结构

以左肩 pitch 为例：

```xml
<joint name="left_shoulder_pitch_joint" type="revolute">
  <origin xyz="0 0.14806 0.42333" rpy="0.2618 0 0"/>
  <parent link="torso_link"/>
  <child link="left_shoulder_pitch_link"/>
  <axis xyz="0 1 0"/>
  <limit lower="-3.14" upper="1.57" effort="40" velocity="9"/>
</joint>
```

| 字段 | 含义 |
|---|---|
| `type="revolute"` | 有上下角度限制的旋转关节 |
| `parent` | 父连杆，这里是躯干 |
| `child` | 子连杆，关节转动会带动它及后续运动链 |
| `origin` | 关节坐标系相对父连杆坐标系的位置和姿态 |
| `axis` | 关节坐标系中的旋转轴，不一定等于基坐标系中的同名轴 |
| `limit` | 模型中的上下限、力矩上限和速度上限 |

对一个旋转关节，应先根据 `origin` 到达关节安装坐标系，再根据关节角 `q` 绕 `axis` 旋转：

```text
T_parent_child = T_origin * R_axis(q)
```

变换相乘有顺序，不能交换。

## 5. 运动学树与 SDK 数组顺序

真实机械连接关系是：

```text
pelvis
└─ torso yaw
   └─ torso_link
      ├─ left shoulder pitch → roll → yaw → elbow → wrist roll → pitch → yaw
      └─ right shoulder pitch → roll → yaw → elbow → wrist roll → pitch → yaw
```

SDK 示例中的 `arm_joints` 数组顺序是：

```text
左臂 7 关节 → 右臂 7 关节 → 腰部 yaw
```

数组顺序只是程序保存和填写命令的顺序，不代表运动学连接顺序。计算任一手腕相对基座的位姿时，腰部变换必须在对应手臂变换之前参与计算。

## 6. 左右臂不是直接复制关系

左右臂的结构近似镜像，但部分关节的符号和范围不同。例如：

```text
左肩 roll：-0.38 ～ 3.40 rad
右肩 roll：-3.40 ～ 0.38 rad
```

因此不能将左臂的 7 个目标角原样复制给右臂。生成镜像姿势时需要逐关节确认符号关系，并分别检查左右关节限位。

腕部 pitch 范围约为：

```text
-0.4625 ～ 0.4625 rad，约 -26.5° ～ 26.5°
```

需要较大手掌俯仰角时，不能只依赖腕部 pitch，肩、肘和腕部需要共同调整。

## 7. 正运动学

左手腕位姿可以概念性地写成：

```text
T_base_left_wrist
  = T_base_pelvis
  * T_waist
  * T_left_shoulder_pitch
  * T_left_shoulder_roll
  * T_left_shoulder_yaw
  * T_left_elbow
  * T_left_wrist_roll
  * T_left_wrist_pitch
  * T_left_wrist_yaw
```

前面的关节会影响其后所有连杆：腰部 yaw 会同时影响左右手腕，腕部 yaw 只影响腕部之后连接的结构。

如果允许腰部参与，单侧基座到手腕包含 8 个可控关节；末端位姿只有位置 3 维和姿态 3 维，因此通常存在多组关节角可以到达同一手腕位姿。多余自由度可用于避开关节极限、自碰撞和不自然姿态。

## 8. 安装 Dex5 后的变换

安装灵巧手后：

```text
T_base_palm = T_base_wrist * T_wrist_Dex5_base
```

其中 `T_wrist_Dex5_base` 是手腕到 Dex5 基座的固定安装变换。若它不准确，手腕关节即使完全跟随计划，实际手掌和指尖仍无法准确到达抓取位姿。

该变换必须由确认过的机械图纸、厂家模型或标定结果获得。

## 9. 当前模型的碰撞检查限制

`h1_2_handless.urdf` 中左右 `wrist_yaw_link` 的 collision 块被注释。直接使用该模型做规划时，腕部附近的碰撞检查可能不完整。

加入 Dex5 后，至少要检查并补全：

- 腕部碰撞几何。
- 灵巧手和安装座的碰撞几何。
- 手与前臂、躯干和另一只手之间的自碰撞。

在碰撞模型完整并验证前，规划成功不能证明实机路径安全。

## 10. 已掌握的关键点

- SDK index 与 URDF 关节名解决不同问题，但必须正确对应。
- `axis` 位于关节坐标系，需要结合 `origin rpy` 理解。
- 单关节变换先应用 `origin`，再绕 `axis` 旋转。
- SDK 数组顺序不等于机械运动链顺序。
- 腰部 yaw 位于双臂共同的上游，会影响左右手腕。
- 左右臂不能简单复制相同目标角。
- URDF limit 不能直接当作首次实机安全速度或工作范围。
- Dex5 安装变换和完整碰撞模型是最终抓取规划的必要条件。
