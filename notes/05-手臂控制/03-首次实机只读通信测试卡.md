# H1-2 首次实机只读通信测试卡

**测试对象**：`code/01-arm-control/arm_state_monitor.cpp`  
**测试性质**：只订阅 `rt/lowstate`，不发布消息  
**状态**：待硬件和现场条件齐备后执行  
**禁止事项**：本测试不运行任何手臂、站立或行走命令

## 1. 测试目的

验证开发电脑能持续收到 H1-2 的 `rt/lowstate`，并获得左右臂和腰部 15 个关节的 `q/dq/tau_est`。

这项结果直接用于未来抓取控制器的状态反馈、超时判断、跟踪误差检测和日志记录。

## 2. 本次测试的安全边界

程序中允许存在：

```text
ChannelSubscriber<LowState_>
```

程序中不允许存在：

```text
ChannelPublisher
Write(
rt/arm_sdk
rt/lowcmd
```

只读程序不会要求机器人改变 FSM，也不会发送目标角、增益或力矩。本测试中不运行其他 SDK 示例。

## 3. 硬性前置条件

以下条件必须全部满足，否则不开始：

- [ ] H1-2 按厂家流程完成正常上电，现场负责人确认当前状态稳定。
- [ ] 实体急停功能已确认，遥控器连接正常。
- [ ] 机器人按现场规范使用吊绳或其他可靠保护。
- [ ] 人员离开双臂、躯干和跌倒可达范围，测试区域已隔离。
- [ ] 开发电脑与机器人交换机使用可靠网线连接。
- [ ] 本机网卡确认是 `enp114s0`；若实际名称变化，先修改测试记录。
- [ ] 不存在正在运行的手臂或全身控制示例。
- [ ] 本次只运行学习仓库中的 `arm_state_monitor`。

即使程序是只读的，机器人本体或其他服务仍可能处于有动力状态，因此实体急停和隔离区不能省略。

## 8. 预期输出

成功建立状态流后，应看到：

```text
State: FRESH
receive rate: 非零且基本稳定
age: 小于500ms
15个关节的q、dq、tau_est
```

按 `Ctrl+C`后应看到：

```text
State monitor stopped. No command was published.
```

第一次测试只记录接收频率，不预设一个未经验证的“正确频率”。

## 9. 立即停止条件

出现以下任一情况，不继续后续测试：

- 机器人发生任何非预期动作：优先使用实体急停并按现场流程处置。
- 运行的文件不是学习仓库中的 `arm_state_monitor`。
- 静态检查发现 Publisher、`Write()`或控制 Topic。
- DDS 初始化报错或持续收不到第一帧状态。
- 状态持续显示 `STALE`或接收频率为 0。
- 任一 `q/dq/tau_est` 显示 `nan`、`inf`或明显异常跳变。
- 关节名称与实际动作/姿态明显不对应。
- 程序无法通过 `Ctrl+C`正常结束。

本程序没有控制机器人，因此机器人意外运动意味着可能存在其他控制源、机器人自身状态变化或现场问题，不能只关闭监视器后继续测试。
